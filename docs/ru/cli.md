# Командная строка

`td-atlas` набирает человек за терминалом. Он дотягивается до того же, что
открывают инструменты MCP. Ниже каждая подкоманда, каждый ключ и то, что
каждому нужно для работы; всё снято с `--help` и `build_parser()` 2026-09-07.

Как поставить, написано в [README](../README.md#install). Что запускать, когда
что-то сломалось, написано в [Починке](troubleshooting.md). Дальше и то и
другое считается сделанным.

Пока virtualenv не активирован, зовите команду по пути. Это
`.venv/bin/td-atlas` или `.venv\Scripts\td-atlas` на Windows. Системный Python
пакета не видит, и `td-atlas doctor` говорит об этом на звене `mcp server`.
Дальше команды пишутся коротко, `td-atlas`.

## Общие ключи идут перед подкомандой

@@kod:1@@

| Ключ | Что делает |
| --- | --- |
| `--db PATH` | взять индекс атомов по этому пути; по умолчанию `~/.td-atlas/atlas.db` |
| `--port N` | говорить с мостом, который слушает этот порт |
| `--project SUBSTR` | говорить с запущенным проектом, чьё имя или путь содержит эту строку |

`--port` и `--project` **выбирают** одну из нескольких запущенных программ.
`td-atlas instances` перечисляет их и помечает ту, до которой эти ключи
дотянутся. Мост зовут шесть команд, и они же принимают выбор: `probe`,
`reload`, `status`, `exec`, `render` и `doctor`. Любой другой команде такой
ключ выдаст ошибку:

@@kod:2@@

У `install --port` то же имя и другой смысл: он ничего не выбирает. Он задаёт
порт, который займёт раскладываемый мост, по умолчанию 9977.

## Что нужно каждой команде

«Мост» здесь значит запущенный TouchDesigner с компонентом моста внутри.

| Команда | Что нужно |
| --- | --- |
| `install`, `instances`, `status`, `doctor`, `log`, `mcp` | ничего; они докладывают, что есть на месте и чего нет. `status` и `doctor` дотягиваются до моста, когда он поднят, и называют его отсутствие, когда его нет |
| `build`, `release-tox`, любое действие `project` | TouchDesigner **установлен** (они читают его поставку или зовут `toeexpand`) |
| `search`, `op` | индекс (`td-atlas build`) |
| `probe` | индекс **и** живой мост |
| `exec`, `render`, `reload` | живой мост |

`instances` отвечает про мосты, ни разу не позвав мост. Он читает реестр
в `~/.td-atlas` и проверяет каждую запись тем, что доступно обеим сторонам.
Принимает ли порт соединение и жив ли ещё процесс. Соединение он открывает
и тут же закрывает, запроса не шлёт, поэтому ни токен, ни версия протокола
здесь не участвуют. Он отвечает и тогда, когда все мосты мертвы или слишком
стары для разговора.

Действия `project` читают индекс, когда он есть, и работают без него. С
индексом точнее разбираются типы: в файле на диске имена типов урезаны,
`tox` на месте `textTOP`, и индекс их разворачивает.

## Установка и проверка

### `td-atlas install`

Раскладывает `bootstrap.py` и `handler.py` в `~/.td-atlas`, выпускает токен
и печатает две строки, которые надо вставить. Первая это
`exec(open(...).read())` для текстпорта TouchDesigner, вторая это
`claude mcp add` для клиента MCP. Запуск заново обновляет разложенные
исходники на месте, а повторная вставка строки bootstrap обновляет на месте
мост внутри проекта.

| Ключ | |
| --- | --- |
| `--port N` | порт, который займёт мост (по умолчанию 9977) |
| `--no-auth` | разложить без токена, тогда мост примет любой местный вызов |
| `--write-mcp-json DIR` | добавить сервер ещё и в `DIR/.mcp.json`, влив его в то, что там уже лежит, и без дубля на втором запуске |

### `td-atlas release-tox`

Собирает мост как `.tox`, который перетаскивают мышью: второй путь установки,
для тех, кто обходится без текстпорта. Токен внутрь не запекается, и обработчик
читает его из `~/.td-atlas/config.json` при старте своего сервера, поэтому
один файл годится для любой машины.

| Ключ | |
| --- | --- |
| `-o, --output PATH` | куда писать (по умолчанию `release/TdAtlas.tox`; каталог создаётся) |

### `td-atlas doctor`

Обходит цепочку звено за звеном, печатает команду починки для каждого
сломанного звена и выходит с ненулевым кодом, когда сломано хотя бы одно.
Звенья такие: окружение, TouchDesigner, индекс, сборка индекса, проход probe,
мост и сервер MCP. Он ещё говорит, сколько распаковок `.toe`/`.tox` лежит
в кеше чтения.

| Ключ | |
| --- | --- |
| `--install-path PATH` | проверять против этого каталога TouchDesigner |
| `--clear-cache` | удалить из кеша каждую распаковку. Кеш и сам ограничен по числу и вытесняет самые давние распаковки; только эта команда забирает назад уже разросшийся кеш, потому что диск ваш |

### `td-atlas status`

Состояние установки, индекса и моста в несколько строк, без мнения в коде
возврата. Строка со счётчиками индекса и есть точный размер корпуса на этой
машине. Эти числа принадлежат вашей сборке TouchDesigner.

### `td-atlas instances`

Каждый запущенный TouchDesigner, который зарегистрировал мост, с портом
и проектом каждого, и как навести на него `--port`/`--project`.

### `td-atlas mcp`

Запускает сервер MCP на stdio. Клиенты MCP заводят его сами по строке, которую
печатает `install`.

## Сборка индекса

### `td-atlas build`

Офлайновый проход читает поставку установленной программы и пишет индекс.
23–30 секунд, без процесса TouchDesigner, без сети.

| Ключ | |
| --- | --- |
| `--install-path PATH` | собрать из этого каталога TouchDesigner, минуя найденный |
| `--no-probe` | убрать напоминание запустить следом `probe` |

### `td-atlas probe`

Проход по живой программе создаёт каждый тип оператора в песочнице
с выключенной готовкой и записывает то, чего нет в документации. Это значения
по умолчанию, диапазоны и зажимы, пункты меню, страницы параметров, число
входов и выходов, короткие имена типов. Нужен открытый TouchDesigner с мостом;
готовка занята примерно минуту.

| Ключ | |
| --- | --- |
| `--chunk N` | сколько типов оператора на один вызов моста (по умолчанию 40) |

### `td-atlas reload`

Раскладывает исходники компонента заново и заставляет живой мост заменить свой
обработчик. Это быстрый круг для правки `src/td_atlas/component/handler.py`.
Только эта команда говорит с мостом, который проверка версии отвергла бы,
и печатает расхождение предупреждением.

## Чтение индекса

### `td-atlas search QUERY`

Полнотекстовый поиск по операторам. Сначала идут имена и подписи, а к тексту
описаний поиск расширяется, когда находок мало.

| Ключ | |
| --- | --- |
| `--family TOP\|CHOP\|SOP\|DAT\|MAT\|COMP` | сузить до одного семейства |
| `--limit N` | сколько находок (по умолчанию 15) |

### `td-atlas op TYPE`

Полная схема оператора. Каждый параметр с типом, значением по умолчанию,
диапазоном, пунктами меню и страницей.

| Ключ | |
| --- | --- |
| `--page NAME` | только параметры с этой страницы |
| `--groups` | перечислить ещё и описанные *группы* параметров (`t`) с их членами (`tx`, `ty`, `tz`). По умолчанию выключено, потому что группу нельзя задать; ключ нужен для чтения вместе с документацией Derivative, которая группы называет |
| `--include-hidden` | показать ещё и параметры, которые TouchDesigner прячет в своём интерфейсе |

## Живая программа

### `td-atlas exec CODE`

Выполняет Python внутри TouchDesigner и печатает stdout, stderr и результат.
`-` читает исходник со stdin. Это произвольный Python, отката он не несёт.

### `td-atlas render PATH`

Сохраняет картинку TOP в файл.

| Ключ | |
| --- | --- |
| `-o, --output PATH` | куда писать (по умолчанию `render.png`) |
| `--width N`, `--height N` | изменить размер; без них берётся собственное разрешение TOP |

### `td-atlas log`

След вызовов моста из `~/.td-atlas/calls.jsonl`; пишет его хост, и он
переживает сессию. Параметры в журнал никогда не попадают. Токен моста вычищается из каждой
строки.

| Ключ | |
| --- | --- |
| `-n, --number N` | сколько последних вызовов (по умолчанию 20) |
| `--failures` | только отказы, с починкой для последнего |
| `--summary` | где вызовы срываются больше всего и что шло дольше всего, по всему журналу |
| `--method M` | только этот метод моста |

## Файлы проекта без запущенного TouchDesigner

`td-atlas project` читает, обыскивает, сравнивает и переписывает файлы
`.toe`/`.tox` с диска. Каждое действие работает с **копией** в кеше, ключ
которого это путь файла, размер и время правки, поэтому ваш файл здесь никто
не трогает. Обе утилиты работают на месте. `toeexpand` пишет
`<name>.tox.dir` и `<name>.tox.toc` рядом со своим входом, а `toecollapse`
отодвигает готовую цель в `<name>.tox.bkp1`, на втором запуске
в `<name>.tox.bkp2`. Проект, который поменялся, распаковывается заново без
просьбы, и `--refresh` остаётся для кеша, испорченного снаружи этой программы.

| Действие | |
| --- | --- |
| `project read FILE` | дерево операторов. `--path /project1` для одного поддерева, `--depth N` (по умолчанию 2), `--params` чтобы включить значения параметров, `--refresh` |
| `project text FILE` | вся сеть как JSON: типы, позиции, флаги, разводка, параметры и содержимое DAT, без потерь. `--path`, `-o/--output FILE`, `--refresh` |
| `project write FILE --text JSON -o OUT` | правленый JSON обратно в `.toe`/`.tox`. Оригинал обязателен, потому что пересборка это заплатка и один текст контейнера не даст. `--text -` читает stdin. Отказывает, когда выходной путь уже занят |
| `project grep FILE PATTERN` | поиск по коду внутри DAT проекта: Python и GLSL, до которых поиск по файлам не доберётся, потому что они лежат внутри контейнера. `--fixed` для буквальной строки, `--limit N` (по умолчанию 100) |
| `project diff FILE OTHER` | сравнение двух проектов по смыслу: что добавили, что убрали, где сменился тип, что перекоммутировали и у чего сменились параметры, плюс построчный diff кода DAT. `--moves` перечисляет узлы, которые только перетащили мышью; их считают отдельно, чтобы движение мыши не хоронило настоящую правку. `--no-text` пропускает diff текста DAT |
| `project expand FILE` | распаковать в кеш и напечатать каталог. `--refresh` |
| `project collapse DIR -o OUT` | упаковать каталог `<name>.tox.dir` обратно в контейнер |
| `project scripts FILE -o DIR` | выписать содержимое каждого DAT отдельными файлами |

Текстовый формат и то, что круг через него сохраняет и что теряет, описан
в [formats.md](formats.md).

### `td-atlas project variant`: сохранённые состояния одного проекта

Вариант держит сеть текстом **и** побайтовую копию `.toe`/`.tox`, откуда он
снят, в `~/.td-atlas/variants/`. Пересборка это заплатка, и без исходника
восстанавливать не во что.

| Действие | |
| --- | --- |
| `project variant save FILE --label L` | сохранить текущее состояние. `--note` говорит, зачем оно понадобилось, `--path` выписывает текстом только одно поддерево |
| `project variant list [FILE]` | что сохранено, по одному проекту или по всем сразу |
| `project variant restore FILE --label L -o OUT` | выписать сохранённое состояние наружу. `-o` может быть каталогом, тогда имя исходного файла остаётся прежним |
| `project variant diff FILE --label L --other M` | сравнить два сохранённых состояния одного проекта. `--moves`, `--no-text` как в `project diff` |

Исходный файл, который поменялся после сохранения варианта, всё равно
восстанавливается, и расхождение попадает в отчёт.

## Сторона MCP

У части здешних команд инструмента MCP нет, у части инструментов нет
подкоманды. Где именно и почему каждый пропуск на месте, объявлено
в [AGENTS.md](../AGENTS.md#cli--mcp-parity) и держится у кода тестом. Сами
инструменты перечислены в
[`plugin/skills/touchdesigner/references/tools.md`](../plugin/skills/touchdesigner/references/tools.md).

Одно расхождение касается общих ключей: со стороны MCP нельзя навестись
на выбранную программу. У `--port`/`--project` нет двойника среди
инструментов, и каждый живой инструмент попадает туда, куда указало
обнаружение моста. Когда мостов запущено больше одного, предупреждение идёт
в каждом ответе.
