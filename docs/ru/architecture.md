# Как это устроено

## Из чего мы исходим

**Почти всё, что агенту нужно знать про TouchDesigner, уже лежит внутри самой
программы.** База параметров на 5 МБ, офлайновая копия всей вики на 182 МБ,
483 разобранных примера, 277 готовых компонентов. Индекс, снятый с
установленной сборки, точен ровно для неё и пересобирается меньше чем
за двадцать секунд без сети (13–16 с по часам за три прогона, замерено
2026-09-12 на сборке 2025.32460).

**TouchDesigner почти ничего не сообщает, когда что-то молча не работает.**
Ветка, которую никто не показывает, не варится. Выключенное устройство вывода
выдаёт тишину. Оператор, упёршийся в процессор, роняет частоту кадров до 3.
Лицензия Non-Commercial делит разрешение надвое. Ошибку не поднимает ни один
из этих случаев, и глаз на сети у агента нет. Ради этой поломки коннектор
и сделан, а ищет её проверка `td_health`.

## Три слоя

@@kod:1@@

Каждый слой стоит сам по себе. Индекс отвечает с закрытым TouchDesigner,
и читатель проектов разбирает файлы тоже с закрытым. Живая копия нужна только
мосту, и его отсутствие возвращается докладом.

## Индекс

Два прохода в одну базу SQLite с FTS5.

**Офлайновый проход** читает бандл: `TDParameterHelp.json`, копию вики,
готовые компоненты, библиотеку примеров, справку по выражениям. Он даёт прозу,
то есть для чего оператор и что значит параметр.

**Проход по запущенной программе** создаёт по одному оператору каждого типа
в песочнице с выключенной готовкой и читает то, чего документация не
записывает: значения по умолчанию, диапазоны и ограничители, пункты меню,
страницы параметров и их порядок, число разъёмов. Он же выводит 71
сокращённое имя типа, сохраняя песочницу и читая обратно то, что записал
TouchDesigner.

Готовка в песочнице выключена. Video Device In TOP, которому дали свариться,
включает камеру.

Каждый проход находит то, чего не видит другой. Справочный файл описывает
654 типа, программа выставляет 647, и 13 из них в справке отсутствуют.
Справка описывает *группы* параметров (`t`) там, где задать можно только
отдельные параметры группы (`tx`, `ty`, `tz`). Поэтому они наследуют прозу
группы, а сами группы помечены как незадаваемые.

## Мост

Web Server DAT и DAT с обратными вызовами, которые **строит скрипт**. Мост
читается глазами и ложится в diff, лежит в системе версий исходным текстом,
а повторный запуск первой строки обновляет его на месте. Запущенный мост
умеет заменить свой обработчик по `td-atlas reload`, и возвращаться
в текстпорт никому не нужно.

Хост и TouchDesigner встречаются в `~/.td-atlas`. Хост кладёт туда исходники
компонента и конфиг с выданным токеном, а первая строка дописывает обратно
файл сессии, где назван занятый порт. После этого рукопожатия клиенту нечего
настраивать.

Ещё три повадки:

- **Пачки выполняются внутри `ui.undo`.** Сорвавшаяся пачка откатывается
  и не оставляет полусети; удавшаяся отменяется одним Ctrl+Z художника, ровно
  как правка руками.
- **Параметры проверяются по индексу до того, как что-то уйдёт.** Имя группы,
  опечатка, пункт меню, которого нет, значение за ограничителем. Эти четыре
  частые ошибки приходят обратно исправлениями.
- **Отрисовка отдаёт пиксели.** TouchDesigner это визуальный инструмент,
  и агент, который не видит его вывода, работает вслепую. Для всего, что
  меняется во времени, один кадр это монетка, поэтому `bridge/filmstrip.py`
  берёт пробы по часам и просит TouchDesigner сложить кадры плиткой
  через numpy.

Запрос выполняется на главном потоке TouchDesigner во время готовки, и это
ограничивает то, что обработчику позволено делать. Кадры внутри одного вызова
не двигаются, поэтому контактные листы и проверки здоровья ведутся с хоста
за два вызова и больше.

## Какая копия и есть ли она вообще

Несколько процессов TouchDesigner могут работать разом, у каждого свой мост
на своём порту. В `~/.td-atlas` лежит ещё и их список. Запись считается
**живой**, когда порт слушает *и* процесс всё ещё есть. Эти два факта хост
и мост проверяют одинаково.

Имя процесса список не записывает. Изнутри TouchDesigner видно его встроенный
интерпретатор, снаружи видно приложение.

Регистрация происходит на том пути установки, которым пользовались. Через
выпущенный `.tox` срабатывает обратный вызов `onServerStart` у Web Server DAT
и делает её. Через вставленную первую строку не срабатывает. Переключение
`active` из скрипта этот вызов не запускает, замерено, поэтому копию
регистрирует сам `bootstrap.py`.

Поэтому `td-atlas instances` единственная команда, которая отвечает на вопрос
о мостах, не делая вызова к мосту. Она открывает порт и закрывает его снова,
ничего не посылая, так что ни токен, ни версия протокола в дело не идут,
и недоступный или устаревший мост всё равно попадёт в список. Выбирают между
ними ключи `--port`/`--project` в CLI. У поверхности MCP такого нет, и причину
даёт `AGENTS.md`.

## Читатель проектов

`toeexpand` превращает контейнер в дерево маленьких текстовых файлов. Чтение
этого дерева даёт структуру, связи, параметры и тот Python и GLSL, что лежит
внутри DAT. Последнее обычно и есть самое важное, и никакой поиск по файлам
туда не дотянется, потому что живёт этот код внутри контейнера.

Всё происходит на копии в кеше; ключом служат путь, размер и время правки.
Поэтому чтение проекта не меняет оригинал и ничего не оставляет рядом с ним.

`diff` сравнивает смысл. Он перечисляет операторы, которые добавили, убрали,
которым сменили тип, которые перевязали и которым поменяли параметры, плюс
построчный diff изменённого кода DAT. Узлы, которые только перетащили мышью,
считаются отдельно, и движение мыши настоящую правку собой не закроет.

Форматы, которых нет в документации, разобраны в [formats.md](formats.md).

## Здоровье

`errors` берёт то, что TouchDesigner называет ошибкой. `bridge/health.py`
берёт всё остальное. Он снимает две пробы с промежутком и сверяет счётчик
готовок каждого оператора с часами кадров.

Остановленная лента времени и ушедшее в фон окно одинаково морозят часы
кадров, и тогда всё выглядит спящим. Оба случая названы своими именами,
и мёртвой сетью не докладывается ни один.

## Правила, по которым это писалось

- **Меряйте, не гадайте.** Почти всё, на чём стоит этот проект,
  в документации не описано. У каждого выведенного факта в комментарии лежит
  доказательство.
- **Честный пробел лучше уверенного вранья.** Две эвристики выбросили именно
  поэтому. Обе выглядели полным успехом и обе врали.
- **Рядом с файлом пользователя не писать.** Инструменты TouchDesigner пишут;
  этот проект сначала копирует.
- **Офлайновые слои держать офлайновыми.** Обычному `pytest` запущенный
  TouchDesigner не нужен вовсе. `pyproject.toml` снимает метку `live`, поэтому
  тест, который звонит живой копии, собирается только тогда, когда его
  позвали по имени. Части тестов TouchDesigner нужен *установленным*, и без
  него они пропускаются. Эти остаются в обычном прогоне, и те же проверки
  проходят на любой машине, где программа стоит.
